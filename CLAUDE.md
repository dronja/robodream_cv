## 1. Мета

Перетворити дослідницький ноутбук на **product-ready систему покращення облич** (face super-resolution / face hallucination): з низькороздільного, розмитого, зашумленого чи стисненого зображення обличчя отримати правдоподібне зображення високої роздільності, **максимально зберігаючи ідентичність** людини.

Кінцевий продукт:
- Python-пакет `facehall` з CLI;
- повний inference-pipeline: детекція → вирівнювання → відновлення → вклеювання назад у кадр;
- REST API (FastAPI) + Docker-образи (CPU і GPU), моделі в ONNX;
- відтворюване навчання й оцінювання з метриками якості та збереження ідентичності;
- документація: model card, опис даних, ліцензії третіх сторін.

## 4. Відомі проблеми legacy-коду (не переносити в новий код)

**Дані й оцінювання**
1. Train/val split без перемішування і без урахування особи (`all_files[:split]` після `rglob`) → одна людина може бути і в train, і у val; val-метрики завищені.
2. Демо-результати (`1.jpg…99.jpg` через `load_images`) беруться з тієї ж папки, що й train — невідомо, чи це не тренувальні зразки.
3. `ds_train` не перемішується (немає `.shuffle()`), seed не фіксований.
4. Три різні деградації в одному ноутбуці — результати не порівнювані:
   - train: HR→LR через `tf.image.resize` (bilinear, `antialias=False` → aliasing);
   - демо Keras: `load_img(target_size=…)` (PIL, за замовчуванням `nearest`) напряму з оригіналу;
   - демо PyTorch: `torchvision.transforms.Resize` (bilinear з antialias).
5. 89×109 → 96×96: непропорційне розтягування; по ширині HR-«еталон» сам є апскейлом (89→96).
6. Деградація — лише чистий даунскейл. Модель не бачила blur, шуму, JPEG чи відеокодеків → погано узагальнюватиметься на реальні знімки.
7. Метрики лише MSE/MAE. Головна мета з README — збереження ідентичності — не вимірюється.
8. Обличчя не детектуються і не вирівнюються: модель працює тільки на готових вирівняних кропах.

**Моделі й код**
9. Змішано два фреймворки (TF/Keras + PyTorch).
10. BatchNorm у residual-блоках — для SR відомо, що шкодить (EDSR, ESRGAN відмовилися від BN).
11. «SRGAN»-генератор архітектурно = FNet (SRResNet, 5 блоків). Отже поганий результат SRGAN — найімовірніше через рецепт навчання (без L1/MSE-претрейну генератора, ваги втрат, мало епох, немає clamp виходу), а не через підхід. **Не відкидати adversarial/perceptual losses через legacy-результат.**
12. `Lambda`-шар у Keras — непереносимий; `load_model` потребує `safe_mode=False`.
13. `load_images(path, …)` ігнорує аргумент `path`; `pixel_shuffle()` визначено, але не використано.
14. README: посилання для «C-Face Network» (arXiv:1503.03832) веде на FaceNet (розпізнавання облич), а не на face hallucination — знайти правильне джерело. Розміри входу в README (32×24, 16×12) не збігаються з кодом (24×24).
15. ~22 MB ваг закомічено в git; `.gitignore` не ігнорує дані й чекпоінти.

## 6. Цільова архітектура

### Inference pipeline

```
вхід (фото / кадр відео)
  → детекція облич (bbox + 5 точок)        ← fallback: bbox/точки від користувача
  → вирівнювання (similarity transform до канонічного шаблону)
  → кроп N×N
  → модель відновлення (×4 / ×8)
  → корекція кольору (опційно)
  → зворотне перетворення + м'яка маска → вклеювання в кадр
  → апскейл фону (опційно)
  → вихід + метадані (модель, версія, параметри, позначка «AI-enhanced»)
```

На обличчях 16–24 px детектори та landmark-моделі ненадійні, тому:
- детекція на bicubic-апскейлі входу;
- ручний bbox як fallback;
- під час навчання — випадкові зсув/поворот/масштаб кропу (alignment jitter), щоб модель була стійкою до неточного вирівнювання.

Маска для вклеювання за замовчуванням — feathered-еліпс (без зовнішніх ваг). Parsing-маска — опційно, з урахуванням ліцензії її ваг (D2).

## 7. Дані

- **Дані не комітимо.** Вони в `data/` (у `.gitignore`) або зовнішньому сховищі. У репо — тільки маніфести (CSV/Parquet: шлях, sha256, джерело, ліцензія, identity_id, split).
- **Split за особою** (identity-disjoint): для CelebA — офіційний partition (перевірено: особи не перетинаються, D8); для джерел без ідентичностей — split за джерелом. Test-набір заморожений і не використовується для підбору гіперпараметрів.
- **Пропорції зберігаються**: вирівнювання + квадратний кроп, без непропорційного resize.
- **HR-еталон не може бути апскейлом**: джерела з роздільністю ≥ цільової (з урахуванням ліцензій, §8).
- **Деградації — на льоту з конфігу** (`configs/degrade/*.yaml`); для val/test — фіксований seed і збережені параметри:
  - blur: ізотропний/анізотропний Gaussian, motion, defocus;
  - downsample: випадкова інтерполяція (bicubic / bilinear / area / nearest), з antialias і без;
  - шум: Gaussian, Poisson, кольоровий і сірий;
  - стиснення: JPEG; опційно H.264/H.265 (сценарій відео й камер);
  - опційно second-order деградація в стилі Real-ESRGAN, grayscale, зсув кольору.
- Окремий **real-world test set**: справжні низькоякісні фото без еталону — для візуальної оцінки й no-reference метрик.
- `docs/DATA.md`: склад, джерела, ліцензії, кількість, як відтворити.

## 9. Моделі та навчання

Еволюція (кожен крок порівнюється з попереднім на **тому самому** test set):

1. **Бейзлайни**: bicubic; порт FNet і CNet у PyTorch 1:1 — точка відліку на новому протоколі.
2. **SRResNet-v2**: без BN, residual scaling, більше блоків; L1 замість MSE.
3. **Perceptual + adversarial** (рецепт ESRGAN): претрейн генератора на L1 → GAN fine-tuning; perceptual (VGG) + adversarial з малою вагою; EMA ваг.
4. **Identity loss**: косинусна відстань ембедингів face-recognition моделі між SR і HR (ліцензії — §8).
5. **Prior-guided модель — запланована комбінація SRResNet + C-Face**: грубий SR → оцінка prior (landmark heatmaps / parsing maps) → точний SR з умовою на prior. Орієнтир — FSRNet. Додатково: втрати на heatmaps/parsing, facial component loss (очі, рот).
6. *(Опційно, пізніше)* генеративні prior-и: codebook/VQ або diffusion-based restoration — якщо дозволяють D2 і обчислення.

Правила навчання:
- Усе через конфіг і CLI, без магічних констант у коді. З кожним запуском зберігаються конфіг, git-хеш, seed, версії бібліотек.
- **Smoke-run обов'язковий** перед повним запуском: кілька сотень зображень, 1–2 епохи, < 5 хв.
- Під 8 GB VRAM: AMP, gradient accumulation, за потреби gradient checkpointing.
- Чекпоінти: `last`, `best` (за основною val-метрикою), EMA. Формат — `safetensors` + JSON з метаданими.
- Повні тренування (довші за ~30 хв) — лише після підтвердження користувача.

## 10. Оцінювання

`facehall eval` рахує:
- **Synthetic test** (є HR): PSNR і SSIM (Y-канал), LPIPS, **ID similarity** (cosine ембедингів SR vs HR), NME за landmarks.
- **Real-world test** (без HR): FID / NIQE + ID similarity з іншим HR-фото тієї ж особи, якщо є.
- Розбивка: за рівнями деградації (легка / середня / важка), масштабом (×4 / ×8) і **підгрупами** (вік, стать, тон шкіри — за наявною розміткою). Face SR схильний до демографічних зміщень (див. дискусію навколо PULSE, 2020).
- Результати — таблиця в `docs/RESULTS.md` + сітка порівняльних зображень, генеруються автоматично.
- **Числа в документації — тільки з реальних запусків.** Не вигадувати, не округлювати «на око».

Quality gates для нової моделі:
- краща за попередню найкращу за LPIPS і ID similarity, без суттєвого падіння PSNR (поріг визначити після Фази 1);
- немає погіршення в жодній підгрупі понад узгоджений поріг;
- ONNX-експорт: max abs diff з PyTorch ≤ 1e-3 на тестовому батчі.

## 11. Відповідальне використання (обов'язкові вимоги)

- Результат — **правдоподібна реконструкція, а не відновлення справжніх деталей**. Чим менший вхід (особливо ×8 з 16 px), тим більше деталей вигадано. Це має бути сказано в README, UI і відповідях API.
- Продукт не позиціонується й не використовується як засіб ідентифікації особи чи як доказ. У розслідуваннях — лише як орієнтир, з оригіналом поруч.
- Кожен вихід маркується: метадані (PNG text / XMP: `AI-enhanced`, модель, версія, параметри, sha256 входу); опційно — видимий водяний знак; розглянути C2PA.
- Опційний режим «кілька варіантів» (для стохастичних моделей) — наочно показує, що відповідь не єдина.
- API за замовчуванням не зберігає завантажені зображення; у логах — жодних зображень чи облич.
- `docs/MODEL_CARD.md`: призначення, out-of-scope, дані, метрики за підгрупами, обмеження.
- Перевірити вимоги щодо персональних/біометричних даних і маркування синтетичного контенту в юрисдикціях використання (GDPR, EU AI Act, законодавство України про захист персональних даних).

## 14. Правила роботи для Claude Code

- Перед зміною прочитай відповідний модуль і його тести; дотримуйся наявних патернів.
- Маленькі тематичні зміни: одна задача — одна гілка / PR. Commit-повідомлення англійською, Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`).
- `legacy/` — тільки читати. Не комітити дані, ваги, `runs/`, `mlruns/`.
- Новий код — з type hints і тестами. Перед комітом: ruff, mypy, pytest.
- Тести не потребують GPU чи датасету: крихітні синтетичні зображення в `tests/fixtures/`.
- **Без підтвердження користувача не можна**: запускати повне навчання; завантажувати великі датасети чи ваги; переписувати git-історію; змінювати публічний CLI/API; додавати залежність або ваги з некомерційною чи невідомою ліцензією.
- Не вигадувати метрики, посилання на статті чи ліцензії — перевіряти або позначати «потребує перевірки».
- Відкриті рішення (§5) не приймати мовчки: спитати або явно взяти значення за замовчуванням і записати в `docs/DECISIONS.md`.
- У кожному PR оновлювати `docs/PROJECT.md` (стан, чекбокси, команди, перевірені факти). Нові факти про проєкт записувати туди, а не в пам'ять сесії.
